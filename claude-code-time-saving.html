副業ライターの僕が、Claude CodeでWordPress入稿を5倍速にした話｜独立準備中の時短実録

副業ライターになって気づいたのは、「書く時間」より「貼る時間」が長い月もあるということでした。この記事は、独立準備中の24歳が、Claude Codeに相談しながら作ったWordPress自動入稿スクリプトで、1記事20分かかっていた入稿作業を4分に短縮した体験の記録です。時短そのものより、浮いた時間で何が変わったかに重心を置いて書いています。

1. 副業ライターの時間が、入稿に食われていく

副業でライター業を始めてから、ある違和感がありました。「書く仕事」のはずなのに、1本仕上げるまでの作業時間のうち、本文を書いている時間よりも、仕上げの装飾や入稿に使っている時間のほうが長い週があったのです。

手順はこうでした。Markdown形式のメモで骨組みを書き、本文を書き足し、推敲し、WordPressの管理画面に貼り付けて、見出しをタグ化し、改行を直し、画像にaltを付け、カテゴリーとタグを設定し、プレビューで崩れを確認する。1記事あたり、入稿作業だけで約20分。

月に5記事書けば、入稿だけで100分。1時間半以上の時間を、頭を使わない「貼る」作業に充てていた計算です。これが週になり月になると、独立準備中の自分にとって、無視できない「静かな消耗」になっていました。

「書く」はクリエイティブな作業なのに、「貼る」はただの転記作業です。この2つが同じ案件のなかで切れ目なく続くと、頭の切り替えで疲れが残る感覚がありました。

この記事は、こういう人に向けて書きました

ライティング経験は積み始めたばかりで、AIツールにも興味はあるけれど、まだ本格的に触れていない人。副業ライター、独立準備中の20代、「書くより貼るに時間を使っている違和感」がある人。1人でも当てはまる人がいればと思って書いています。

2. Claude Codeを選んだのは「自分で動かせた」から

AIツールと言えばChatGPT、Gemini、Claudeあたりが候補に挙がります。この中からClaude Codeを選んだのは、「エンジニアじゃない自分でも、対話するだけで動くスクリプトが手元に残る」感覚があったからです。

最初にお願いしたのは、「Markdown原稿をWordPressに自動投稿するPowerShellスクリプトを作りたい」という、素人丸出しの一言でした。Claude Codeは、必要な認証方法（Application Password）、使うAPI（REST API）、Markdownを変換する処理まで、1つずつ対話形式で組み立ててくれました。

途中、Windows PowerShellでの文字コードの罠にハマったり、記号の扱いで動かなくなったりしましたが、エラーを貼り付けると原因と修正案が返ってくるので、1人で詰まる時間がほぼありませんでした。

派手なAI活用の記事では「AIに書かせた」の話が目立ちますが、僕にとって一番価値があったのは「AIに頼りながら、自分の手で道具を作れた」実感でした。使い終わっても、スクリプトは自分のPCに残り続けます。

実装の詳細は、別のポートフォリオ記事（Markdown原稿からWordPressへ記事を一括公開する｜REST API × PowerShellの実装ガイド）で解説しています。本記事では「作ったあと、何が変わったか」を主に書きます。

3. WP入稿で変わった3つのこと

スクリプトができあがってから、1記事あたりの入稿時間はこう変わりました。

BEFORE
20分 / 記事
AFTER
4分 / 記事

単純計算で約5倍速です。月に5記事なら、入稿時間が100分から20分へ短縮され、1時間20分が別の作業に回せる計算になります。ただ、数字より大事な変化が3つありました。

変化1：単純作業からの解放

「書く」モードと「貼る」モードの切り替えがなくなり、1本仕上げたあとの疲労感が明らかに減りました。原稿を書き終えた瞬間、コマンド1本で下書き化が終わるので、推敲に集中できます。

変化2：見出し整形や記号崩れの心配がゼロに

手作業の入稿では、h2のタグ化を忘れたり、全角括弧が半角に変換されていたりと、小さな事故が月1回は起きていました。スクリプトが同じ処理を毎回同じ精度でやってくれるので、ミス由来の再修正時間がなくなりました。

変化3：執筆の推敲や、新しい案件への挑戦に時間を回せる

一番大きかったのはこれでした。浮いた80分で、仕上がった原稿を推敲する余裕が生まれ、提案文の精度を上げる時間ができ、新しいテーマへの応募が増えました。結果として、1本あたりの単価も少しずつ上げられるようになっています。

4. AI時短でも、やらないと決めた2つのこと

AIで時間が浮くとわかると、つい「もっと自動化できないか」「他のツールも試したい」と考えてしまいます。ただ、独立準備中で資金に余裕がない僕にとっては、「やらないこと」を決めるほうが大事でした。

やらないこと1：AIに記事の本文を書かせる

これは、僕のライター業そのものを壊してしまう選択です。読者が記事に求めるのは「書き手の体験と視点」だと信じているので、本文の執筆は自分の手で続けることにしました。AIは、構成の壁打ちや、タイトル案の洗い出しに使っています。

やらないこと2：流行りのAIツールを全部触る

月に新しいAIサービスが次々と出てきますが、追いかけ続けると「どれも中途半端」で終わります。僕はClaude Code 1つに絞って、できることを深掘りする運用に落ち着きました。深く触った道具のほうが、結果的に長く使えています。

「捨てる技術」は、ライティングでも生き方でも効くと感じます。やることを増やすより、やらないことを決めるほうが、結果が出るまでの距離が短くなりました。

5. 読者へ：今日から1つだけ自動化する

この記事を読んでくださった方で、「WordPressに月1本でも入稿している」人がいれば、Claude Codeに同じ相談をしてみる価値があります。無料枠から始められて、エンジニアでなくても動かせるからです。

最初の一歩は、こんなプロンプトからで十分です。

目的 Markdown原稿をWordPressに下書きとして自動投稿したい
環境 Windows 10 + PowerShell、WordPressはApplication Password有効
依頼 Markdownファイルを引数に取り、REST API経由でWPに下書き投稿するスクリプトを作ってください

「全部を一気に自動化する」のではなく、「自分の作業時間のうち、1番無駄に感じる1工程」を切り出すのがコツです。全部やろうとすると、どこから手を付けるかで動けなくなります。1つだけ選ぶなら、「同じ作業を繰り返している」ところから。

おわりに：時短は目的ではなく、取り戻した時間で何をするか

「時短」の数字だけを追うと、ゴールが見えなくなります。本当に大事なのは、浮いた時間を何に使うかです。

僕の場合は、推敲に時間を回したこと、新しいテーマに挑戦できたこと、そして、ライティングそのものへの集中を取り戻せたことが、記事単価を上げたりポートフォリオを育てたりする好循環につながりました。独立準備というゴールに向けて、確実に距離を縮められている実感があります。

Claude Codeは、僕にとっての「貼る作業からの解放装置」でした。あなたにとっての「静かな消耗」も、きっと1つあるはずです。それを1つだけ、相談してみる。そこから始まる変化は、思っているより大きいかもしれません。

本記事は、2026年10月時点での筆者個人の運用実例に基づく体験レポートです。数字（1記事20分→4分）はローカルWordPress環境（Local by Flywheel）で実測した値で、環境や運用方法によって変動します。業務導入時は、必ずテスト環境での検証と、クライアントとの事前合意のうえでご判断ください。
